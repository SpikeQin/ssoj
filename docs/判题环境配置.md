# 判题环境配置

## 症状

提交代码后判题失败，页面或日志出现：

```
判题过程出现异常：Cannot run program "g++" (in directory ".\judge-workspace\submission-3"):
CreateProcess error=2, 系统找不到指定的文件。
```

报错里的程序名可能是 `g++`、`gcc`、`javac` 或 `java`，含义都一样：**运行后端的那个进程找不到这个程序**。

## 原因

判题不是"纯 Java 逻辑"，它要在本机真实调用编译器：

| 语言 | 用到的程序 |
| --- | --- |
| C | `gcc` |
| C++ | `g++` |
| Java | `javac`（编译）与 `java`（运行） |

这些程序不随项目分发，**每台电脑都要自己装好**，并且把它们的 `bin` 目录**写进项目配置**（`application.properties`）。判题只认配置里的目录，不读取系统 PATH。

## 目录怎么选

MinGW 解压后（示例是 `C:\mingw64`）应该能看到：

```
C:\mingw64\bin\gcc.exe
C:\mingw64\bin\g++.exe
```

配置里要填的是 **`C:\mingw64\bin`** 这一层，不是上一级 `mingw64`。装在 `D:\tools\mingw64` 之类的目录也一样，填对应的 `bin` 即可。

## 配置步骤

### 1. 安装 JDK 21

后端本身要用 JDK 21，能启动服务说明 JDK 已装好；但要确认是 **JDK** 而不是 JRE，JDK 才带 `javac`。

### 2. 安装 / 解压 MinGW-w64

- 版本：x86_64、posix-seh（本项目在 **MinGW-W64 8.1.0** 上验证通过）
- 解压到任意目录（示例为 `C:\mingw64`），确认 `<目录>\bin\gcc.exe` 与 `<目录>\bin\g++.exe` 存在

### 3. 在配置里写死 bin 目录（必填）

打开 `src/main/resources/application.properties`，把 C/C++ 与 Java 的工具链目录分别写上：

```properties
judge.languages.c.bin-dir=C:/mingw64/bin
judge.languages.cpp.bin-dir=C:/mingw64/bin
judge.languages.java.bin-dir=C:/Program Files/Java/jdk-21/bin
```

说明：

- 判题时会在该目录下找 `gcc` / `g++` / `javac` / `java`，**不依赖系统 PATH**；
- 路径用 `/` 分隔，带空格也没问题（JDK 的 `Program Files` 可以直接写）；
- **不再回退系统 PATH**：留空或目录下找不到程序时，提交会判为系统错误并提示具体原因；
- 改完**重启后端**即可生效，不需要重启 IDEA。

### 4. 验证判题

启动后端，用学生账号提交一段最简单的 C++：

```cpp
#include <iostream>
int main(){ int a, b; std::cin >> a >> b; std::cout << a + b; return 0; }
```

能出判题结果（哪怕是 Wrong Answer）就说明编译运行链路通了；C 与 Java 各提交一次一并验证。

> 实测：把系统 PATH 里的 MinGW 和 JDK 全部去掉，只保留上面三行配置，C、C++、Java 三种语言都 11/11 通过；
> 把 `c.bin-dir` 故意改成不存在的目录，提交会返回"在 D:/no-such-dir 下找不到 gcc，请检查 judge.languages.c.bin-dir"。

## 工具链装在其它位置怎么办

直接改上面第 3 步的三行配置即可，例如 MinGW 在 `D:\tools\mingw64`、JDK 在 `D:\Java\jdk-21`：

```properties
judge.languages.c.bin-dir=D:/tools/mingw64/bin
judge.languages.cpp.bin-dir=D:/tools/mingw64/bin
judge.languages.java.bin-dir=D:/Java/jdk-21/bin
```

改完重启后端。**不需要改系统环境变量，也不需要重启 IDEA**；路径带空格也可以。

> 注意：不要把绝对路径写进 `compile-command`。判题按空格拆分命令，`C:\Program Files\...` 这种带空格的路径会被拆坏；
> 用 `bin-dir` 则没有这个问题。

## 常见报错对照

| 报错 | 原因 | 处理 |
| --- | --- | --- |
| `未配置语言 c/cpp/java 的工具链目录` | `bin-dir` 留空 | 按第 3 步填上该语言的 `bin` 目录 |
| `在 ... 下找不到 gcc / g++ / javac` | `bin-dir` 写错或程序不在该目录 | 检查路径是否指向 `bin`，目录里是否有对应 exe |
| `Cannot run program "..."` | 目录里有程序但缺少依赖 DLL 或没有执行权限 | 使用完整的 MinGW / JDK 安装包 |
| `Cannot run program "javac"` | 只装了 JRE | 安装完整 JDK 21 |
| 编译报 `stdc++.h` 相关错误 | MinGW 8.1 在 C++17 下的已知问题 | 项目已配置 `-std=gnu++14`，不要改成 c++17 |
| 提交后一直 Pending | 提交请求失败（间隔限制、题目下线、队列满）或后端没运行 | 看浏览器 Network 里 `submissions` 请求的返回信息 |
| 判题结果里只有 System Error | 环境类错误 | 看提交详情里的错误提示，可以直接定位是哪个目录/程序的问题 |
