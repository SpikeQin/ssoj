# 判题环境配置（组员必读）

## 症状

提交代码后判题失败，页面或日志出现：

```
判题过程出现异常：Cannot run program "g++" (in directory ".\judge-workspace\submission-3"):
CreateProcess error=2, 系统找不到指定的文件。
```

报错里的程序名可能是 `g++`、`gcc`、`javac` 或 `java`，含义都一样：**运行后端的那个进程找不到这个程序**。

## 原因

判题不是"纯 Java 逻辑"，它要在本机真实调用编译器：

| 语言 | 用到的程序 |
| --- | --- |
| C | `gcc` |
| C++ | `g++` |
| Java | `javac`（编译）与 `java`（运行） |

这些程序不随项目分发，**每台电脑都要自己装好，并且加进 PATH**。另外，Windows 进程只在启动时读取一次环境变量——**改完 PATH 后必须完全退出 IDEA 再打开**，否则 IDEA 里的 JVM 用的还是旧环境。

## 目录约定：统一放在 `C:\mingw64`

本组统一使用 **`C:\mingw64`**，解压后应有：

```
C:\mingw64\bin\gcc.exe
C:\mingw64\bin\g++.exe
```

需要加入 PATH 的是 **`C:\mingw64\bin`** 这一层（不是 `C:\mingw64`）。

> 把压缩包解压到 `C:\` 即可得到该路径。如果解压后变成 `C:\mingw64\mingw64\bin`，说明多套了一层目录，需要把里面的 `mingw64` 移动到 `C:\`，或者直接把实际的那个 `bin` 目录加入 PATH。

## 配置步骤

### 1. 安装 JDK 21

后端本身要用 JDK 21，能启动服务说明 JDK 已装好；但要确认是 **JDK** 而不是 JRE，JDK 才带 `javac`。

### 2. 放置 MinGW-w64

- 版本：x86_64、posix-seh（本项目在 **MinGW-W64 8.1.0** 上验证通过）
- 解压到 `C:\`，确认 `C:\mingw64\bin\gcc.exe` 与 `C:\mingw64\bin\g++.exe` 存在

### 3. 添加 PATH

此电脑 → 右键属性 → 高级系统设置 → 环境变量 → 选中**用户变量**里的 `Path` → 编辑 → 新建 → 输入：

```
C:\mingw64\bin
```

→ 确定（连点三层）。

### 4. 重启 IDEA 并验证

**完全退出 IDEA（File → Exit）再重新打开**，然后新开一个 cmd 窗口（Win+R 输入 `cmd`）执行：

```cmd
where g++
where javac
```

两条都要输出实际路径，例如：

```
C:\mingw64\bin\g++.exe
C:\Program Files\Java\jdk-21\bin\javac.exe
```

再执行 `g++ --version` 能打印版本号即可。

### 5. 验证判题

启动后端，用学生账号提交一段最简单的 C++：

```cpp
#include <iostream>
int main(){ int a, b; std::cin >> a >> b; std::cout << a + b; return 0; }
```

能出判题结果（哪怕是 Wrong Answer）就说明编译运行链路通了。

## MinGW 装在别的位置怎么办（推荐用配置，不必改系统 PATH）

在 `src/main/resources/application.properties` 里把工具链目录填上：

```properties
# MinGW 或 JDK 的 bin 目录，留空则使用系统 PATH
judge.toolchain-dir=D:/tools/mingw64/bin
```

然后**重启后端**（不用重启 IDEA，也不用改系统环境变量）。判题时会把该目录下的
`gcc` / `g++`（以及 `javac` / `java`，如果它们也在这个目录里）优先作为可执行文件使用，
路径带空格也能正常工作。

> 实测：把 MinGW 从系统 PATH 里去掉，只配置 `judge.toolchain-dir`，C++ 提交依然 11/11 通过。

如果仍然想用系统 PATH：把实际的 `bin` 目录加进 PATH 后，必须**完全退出 IDEA 再启动**，
并用新开的 cmd 执行 `where g++` 确认——已在运行的 IDEA 进程不会读取新的 PATH。

另一种备选是直接改编译命令（仅适用于路径不含空格的情况）：

```properties
judge.languages.c.compile-command=D:/tools/mingw64/bin/gcc.exe main.c -o main -O2 -std=c11
judge.languages.cpp.compile-command=D:/tools/mingw64/bin/g++.exe main.cpp -o main -O2 -std=gnu++14
```

路径用 `/` 且不能有空格（判题按空格拆分命令），所以这种方式对 `C:\Program Files\...` 下的 JDK 不适用。

## 常见报错对照

| 报错 | 原因 | 处理 |
| --- | --- | --- |
| `Cannot run program "g++"` | 没装 MinGW，或 PATH 没生效 | 按上面步骤安装并重启 IDEA |
| `Cannot run program "javac"` | 只装了 JRE | 安装完整 JDK 21 |
| 编译报 `stdc++.h` 相关错误 | MinGW 8.1 在 C++17 下的已知问题 | 项目已配置 `-std=gnu++14`，不要改成 c++17 |
| 提交后一直 Pending | 提交请求失败（间隔限制、题目下线、队列满）或后端没运行 | 看浏览器 Network 里 `submissions` 请求的返回信息 |
| 判题结果里只有 System Error | 环境类错误 | 看后端控制台异常，多半仍是 PATH 问题 |
| 装了 MinGW、PATH 也对，仍报找不到 g++ | 后端进程环境是旧的 | 完全退出 IDEA 再启动，或改用 `judge.toolchain-dir` |

## 把项目发给组员时

1. 发整个 `SSoj` 目录（包含 `sql`、`docs`、`web`）。
2. 对方按 `sql/01_schema.sql` → `02_init_data.sql` → `03_problem_data.sql` 的顺序建库。
3. 修改 `src/main/resources/application.properties` 里的数据库账号密码为对方本机的。
4. 让对方先按本文档第 4 步验证 `where g++` 与 `where javac`，再启动项目。

> 提示：`03_problem_data.sql` 会清空题目、用例、竞赛与提交记录，重新导入前确认不需要保留现有数据。
